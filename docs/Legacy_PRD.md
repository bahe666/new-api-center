# SenseCore API 中心改造 — 产品需求文档 (PRD)

---

## 1. 执行摘要

### 问题陈述

SenseCore（商汤大装置）现有 API 中心嵌套在帮助中心内，20 个产品共 245 个 API 全部堆砌在一个超长滚动页面上（约 6000px），没有按场景分组、没有搜索过滤、没有新手引导。外部开发者反馈**界面难看、查找不便、不知道如何上手**，导致 API 接入效率低、开发者体验差。

### 解决方案

将 API 中心从帮助中心拆分为**独立门户网站**，重新设计 API 目录和导航体系：
- 全产品侧边栏 + 树形分组导航，替代现有的长列表堆叠
- 全局模糊搜索 + 产品内搜索，缩短查找路径
- 分步式新手引导系统，降低上手门槛
- API 详情页内容原封不动保留（参数/响应/代码示例/在线调试），通过同源 iframe 嵌入

### 成功标准

- 开发者从进入 API 中心到找到目标 API 的操作路径显著缩短
- 新用户能通过引导流程独立完成 API 查找和理解
- 所有 API 详情内容与原站完全一致，无信息丢失
- 门户可独立部署，不依赖帮助中心框架

## 2. 用户体验与功能

### 2.1 用户画像

| 画像 | 描述 | 核心需求 |
|---|---|---|
| **新手开发者** | 首次接触 SenseCore API 的外部开发者，不了解产品体系和 API 结构 | 了解有哪些产品、每个产品能做什么、API 怎么调用 |
| **熟练开发者** | 已接入部分 SenseCore 服务的开发者，需要查阅新产品或新接口的文档 | 快速找到特定 API 的参数、响应格式和代码示例 |
| **集成架构师** | 负责评估和规划 SenseCore API 接入方案的技术决策者 | 浏览全部产品能力，了解 API 覆盖范围和设计风格 |

### 2.2 用户故事与验收标准

#### US-01: 浏览全部产品

**作为** 一个外部开发者，**我想** 看到 SenseCore 所有的云产品及其 API 数量，**以便** 快速了解平台提供的能力范围。

**验收标准：**
- 左侧侧边栏展示全部 20 个产品，每个显示产品名和 API 数量
- 产品可点击展开，显示该产品下按功能分组的 API 列表
- 产品可点击折叠，支持多个产品同时展开/折叠

#### US-02: 查看产品 API 列表

**作为** 一个开发者，**我想** 查看某个产品下所有 API 的名称、描述和请求路径，**以便** 找到我需要的具体接口。

**验收标准：**
- 点击侧边栏中的产品名后，右侧内容区显示该产品的 API 列表表格
- 表格每行包含：API 名称、描述、请求路径（带 HTTP Method 彩色标注）
- 表格行可点击，跳转到对应 API 详情页

#### US-03: 全局搜索

**作为** 一个开发者，**我想** 通过关键词搜索找到跨产品的 API 接口，**以便** 在不知道 API 归属哪个产品时也能快速定位。

**验收标准：**
- 顶部导航栏有搜索输入框，支持 ⌘K 快捷键唤起
- 输入关键词后，搜索框下方出现下拉面板
- 下拉面板分两组展示结果：「产品」（最多 3 个）和「API 端点」（最多 8 个）
- 结果显示产品名/API 名（关键词高亮）、Method、所属产品、路径
- 点击结果直接跳转到对应页面
- 支持键盘导航（↑↓ 选择、↵ 确认、ESC 关闭）

#### US-04: 产品内搜索

**作为** 一个开发者，**我想** 在某个产品内搜索特定 API，**以便** 在 API 数量较多的产品中快速过滤。

**验收标准：**
- 侧边栏顶部有搜索框，输入关键词后过滤当前展示的产品和 API
- 产品的计数器实时更新为匹配数
- 清空搜索框后恢复全量展示

#### US-05: 查看 API 详情

**作为** 一个开发者，**我想** 查看某个 API 的完整文档（请求参数、响应格式、代码示例、在线调试），**以便** 直接进行接口调用。

**验收标准：**
- API 详情页左侧保留产品侧边栏（当前 API 高亮），右侧展示详情内容
- ECS 产品的 10 个 API 详情内容与原站（`console.sensecore.cn`）完全一致
- 详情内容包含：API 标题、HTTP Method + 路径、Query Parameters（参数名/类型/描述）、Response Schema、Bearer Token 认证、Send API Request 调试按钮、代码示例
- 内容不做任何修改或简化

#### US-06: 新手引导

**作为** 一个首次使用的开发者，**我想** 有一个分步教程带我了解 API 中心的各个功能区域，**以便** 快速上手。

**验收标准：**
- 顶部导航栏有「新手指引」按钮
- 点击后启动 9 步分步引导：
  - 列表页 5 步：侧边栏产品列表 → 侧边栏搜索 → API 表格 → 全局搜索 → 引导用户点击 API
  - 详情页 3 步：API 标题与路径 → 请求参数 → 调试面板
  - 完成提示
- 每步高亮对应 UI 元素（聚光灯效果），旁边显示说明卡片
- 支持「下一步」和「跳过」操作
- 引导用户点击 API 进入详情页时，等待用户自行操作（不自动跳转）
- 从详情页点击「新手指引」时，自动跳回列表页重新开始
- 首次访问时按钮有脉冲动画提示

### 2.3 非目标（Not In Scope）

- **不做** 在线 API 调试器重构（保留原站的 Send API Request 功能）
- **不做** 用户登录/注册/Token 管理（用户自行在 SenseCore 控制台获取）
- **不做** API 版本管理（暂无版本切换需求）
- **不做** 暗色模式
- **不做** 非 ECS 产品的详情页内容抓取（其余产品使用 iframe 加载原站）
- **不做** 移动端适配（桌面端优先）

## 3. 技术规格

### 3.1 架构概览

```
┌─────────────────────────────────────────────────┐
│                  Vercel (CDN)                    │
│  ┌─────────────────────────────────────────────┐│
│  │           UmiJS 4 SPA 静态文件              ││
│  │  ┌──────────┐ ┌──────────┐ ┌─────────────┐ ││
│  │  │ 产品列表 │ │ API 详情 │ │  静态 HTML  │ ││
│  │  │  页面    │ │  页面    │ │ (ECS 10页)  │ ││
│  │  └──────────┘ └──────────┘ └─────────────┘ ││
│  └─────────────────────────────────────────────┘│
│                                                  │
│  API 详情加载方式:                               │
│  - ECS: 同源 iframe → /api-docs/ecs/*.html      │
│  - 其他: 跨域 iframe → console.sensecore.cn     │
└─────────────────────────────────────────────────┘
```

### 3.2 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 框架 | UmiJS 4 (@umijs/max) | 约定式路由，内置状态管理 |
| 样式 | Sass (SCSS) | 模块化样式，BEM 命名 |
| 组件库 | Ant Design 5 | 按需引入，仅用 ConfigProvider |
| 状态管理 | UmiJS useModel | 全局状态（搜索、引导开关） |
| 部署 | Vercel | 静态文件托管 + CDN + 路由重写 |

### 3.3 路由结构

| 路由 | 页面 | 说明 |
|---|---|---|
| `/` | — | 重定向到 `/apis/ecs` |
| `/apis/:product` | 产品 API 列表 | 侧边栏 + API 表格 |
| `/apis/:product/:endpoint` | API 详情 | 侧边栏 + iframe 内容 |

### 3.4 数据结构

**产品元数据** — 20 个 TypeScript 数据文件，每个包含：
- 产品 ID、名称、缩写、描述、所属领域
- API 分组（`groups`），每组包含端点列表
- 每个端点：ID、名称、描述、Method、路径、详情页 URL

**API 详情内容** — 两种加载方式：
- ECS（10 个 API）：从原站抓取 `.theme-doc-markdown` HTML，存为静态文件，引用原站 Docusaurus CSS
- 其他产品（235 个 API）：iframe 直接加载原站 URL

### 3.5 搜索实现

客户端模糊搜索，匹配范围：
- 产品名（中/英文）
- 产品缩写
- API 端点名称
- API 端点描述
- API 请求路径

搜索结果限制：产品最多 3 个，端点最多 8 个。

### 3.6 集成点

| 系统 | 集成方式 | 说明 |
|---|---|---|
| SenseCore 帮助中心 | iframe 嵌入 | 详情页加载原站 Docusaurus 文档 |
| SenseCore 控制台 | 外部链接 | 导航栏「控制台」按钮跳转 |
| Docusaurus CSS | CDN 引用 | ECS 静态 HTML 引用 `styles.fcac779d.css` |

### 3.7 安全与隐私

- 门户为纯静态网站，无后端服务，不收集用户数据
- 不存储任何 API Token 或用户凭证
- API 调试功能由原站 Docusaurus 页面内的 Send API Request 按钮提供，Token 在浏览器端输入，不经过门户
- iframe 加载原站内容遵守浏览器同源策略

## 4. 页面规格

### 4.1 全局导航栏

- 高度 64px，sticky 定位，backdrop-filter 模糊背景
- 左侧：SC Logo + "SenseCore API" + "API 目录" 链接
- 右侧：全局搜索框（带 ⌘K 提示）+ 「新手指引」按钮 + 「控制台」外链按钮

### 4.2 产品 API 列表页（`/apis/:product`）

**左侧侧边栏（240px）：**
- 搜索框
- 全部 20 个产品列表，每项包含：展开/折叠箭头、彩色缩写图标、产品名、API 计数
- 当前产品自动展开，显示 API 按功能分组的树形列表
- 搜索时计数器显示匹配数

**右侧内容区：**
- 面包屑：仅显示当前产品名
- 产品标题 + 描述
- 搜索框 + API 总数
- API 列表表格（API 名称 / 描述 / 请求路径含 Method 彩色前缀）

### 4.3 API 详情页（`/apis/:product/:endpoint`）

**左侧侧边栏（240px）：**
- 与列表页共享，当前 API 蓝色高亮

**右侧内容区：**
- iframe 加载 API 文档（ECS 加载本地静态 HTML，其他产品加载原站）
- iframe 占满剩余空间

### 4.4 新手引导

- 全屏半透明遮罩 + 聚光灯高亮目标元素
- 说明卡片（步骤指示器 + 文字 + 跳过/下一步按钮）
- 智能定位：卡片自动选择不与高亮区重叠的方向
- 详情页步骤精确定位 iframe 内部元素（同源可访问 DOM）

## 5. 风险与路线图

### 5.1 路线图

| 阶段 | 范围 | 状态 |
|---|---|---|
| **MVP（当前）** | 产品列表 + 搜索 + ECS 详情 + 新手引导 + Vercel 部署 | ✅ 已完成 |
| **v1.1** | 抓取全部 20 个产品的详情页内容（消除跨域 iframe 依赖） | 待规划 |
| **v1.2** | 快速入门指南页面（认证流程、SDK 安装、第一次调用） | 待规划 |
| **v2.0** | 自定义域名、API 变更订阅、开发者反馈收集 | 待规划 |

### 5.2 技术风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 原站 Docusaurus CSS 更新导致 ECS 详情样式错乱 | ECS 10 个 API 详情页渲染异常 | CSS 文件 URL 包含 hash，可固定版本；定期检查并更新 |
| 非 ECS 产品 iframe 跨域被 X-Frame-Options 拦截 | 部分产品详情页无法显示 | v1.1 中抓取所有产品的详情内容，消除跨域依赖 |
| 原站 API 端点增删导致数据过时 | 门户展示的 API 列表与原站不一致 | 建立定期同步机制，或从 OpenAPI Spec 文件自动生成数据 |
| Vercel 免费额度用尽 | 门户无法访问 | 静态文件可部署到任意 CDN，不强依赖 Vercel |

### 5.3 依赖项

| 依赖 | 类型 | 风险等级 |
|---|---|---|
| `console.sensecore.cn` 可访问性 | 运行时（iframe + CSS） | 高 — 非 ECS 产品详情依赖此站点 |
| 原站 API 文档内容不变 | 构建时（ECS 静态 HTML） | 中 — 原站内容更新后需重新抓取 |
| UmiJS 4 生态 | 构建时 | 低 — 成熟框架 |
