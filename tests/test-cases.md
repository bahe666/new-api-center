## TC-05: ECS API 详情页内容一致性（重点）

### 通用前置条件
对于 ECS 的每个 API，需要在新门户打开详情页，同时在原站打开对应详情页，逐项对比。

原站 URL 格式: `https://console.sensecore.cn/micro/help/docs/API/ecs/{slug}`

ECS 10 个 API 的原站 slug 映射:
| API 名称 | 原站 slug |
|---|---|
| 获取云服务器实例列表 | e-c-s-data-plane-service-list-ecs-inss |
| 绑定云服务器实例卷 | e-c-s-service-attach-volume |
| 启动云服务器实例 | e-c-s-service-boot-ecs-instance |
| 删除云服务器实例 | e-c-s-service-delete-ecs-instance |
| 卸载云服务器实例磁盘 | e-c-s-service-detach-volume |
| 查看云服务器实例详情 | e-c-s-service-get-ecs-instance |
| 重启云服务器实例 | e-c-s-service-reboot-ecs-instance |
| 重置云服务器实例密码 | e-c-s-service-reset-password |
| 停止云服务器实例 | e-c-s-service-stop-ecs-instance |
| 更新云服务器实例 | e-c-s-service-update-ecs-instance |

### TC-05-01 ~ TC-05-10: 逐 API 内容对比

对每个 ECS API 执行以下检查清单：

**A. 标题与路径**
- [ ] A1: API 标题文字完全匹配原站（如「获取云服务器实例列表」vs 原站 h2 文本）
- [ ] A2: HTTP Method 匹配（GET/POST/PUT/DELETE）
- [ ] A3: 请求路径匹配（如 `/compute/ecs/data/v1/ecsInstances`）
- [ ] A4: Base URL 匹配：`https://ecs.cn-sh-01.sensecoreapi.cn`

**B. 请求参数**
- [ ] B1: Query Parameters 参数名逐一匹配原站（顺序可不同，但名称必须完全一致）
- [ ] B2: 每个参数的类型匹配（string/int32/boolean 等）
- [ ] B3: 每个参数的描述文字匹配
- [ ] B4: 参数总数匹配（不多不少）
- [ ] B5: 如有 Body Parameters / Path Parameters，同样逐一匹配
- [ ] B6: 必填/选填标记匹配（如果原站有标注 required）

**C. 响应**
- [ ] C1: Response 状态码匹配（200、default 等）
- [ ] C2: Response 描述匹配（如「OK」）
- [ ] C3: Response Content-Type 匹配（application/json）
- [ ] C4: Response Schema 字段名匹配
- [ ] C5: Response Schema 字段类型匹配
- [ ] C6: Response Schema 字段描述匹配（如果原站有描述）

**D. 代码示例**
- [ ] D1: 代码示例存在（至少有一种语言）
- [ ] D2: 代码示例中的 URL 与 Base URL + 路径拼接一致
- [ ] D3: 代码示例中的 Header 包含 Accept 和 Authorization

**E. 样式与布局**
- [ ] E1: Parameters 使用可展开/折叠的面板展示（与原站 `<details>` 元素一致）
- [ ] E2: 参数名加粗显示
- [ ] E3: 参数类型用不同样式标注（如灰色、斜体或 badge）
- [ ] E4: Response 区域有状态码 Tab 或 badge（200/default）
- [ ] E5: 代码块有深色背景和语法高亮
- [ ] E6: 整体布局与原站一致：左侧参数文档 + 右侧代码示例/Try It 面板
- [ ] E7: 不存在原站没有的额外内容（不能凭空添加参数或字段）

**F. 导航**
- [ ] F1: 上一页/下一页链接存在且指向正确的相邻 API
- [ ] F2: 面包屑显示「云服务器 ECS › {当前 API 名称}」
